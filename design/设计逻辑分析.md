# Finance Block 代码块渲染重设计 · 设计逻辑分析

> 分析对象：`redesign/finance-block-redesign.html`
> 性质：单文件 HTML 原型（自包含 CSS + 少量 JS），用于验证 6 类财务代码块的「重设计渲染表现」，未改动插件源码。
> 分析视角：从**设计系统 → 组件语法 → 数据架构 → 交互/可访问性 → 可商榷点**逐层拆解其设计逻辑。

---

## 0. 一句话总纲

原型的核心设计命题是：**以 `fin-beancount`（复式分录）为唯一真源，把原本「平铺的代码块/表格」重做成一套视觉语法统一、语义着色一致、信息密度分级的卡片化视图族**，让 6 类财务块在 Obsidian 阅读视图里既各自承担不同角色，又共享同一套设计语言。

---

## 1. 设计系统（Design Tokens）

原型用 CSS 自定义属性搭了一套**主题无关的 token 层**，这是整份设计能「明暗一键切换」「组件可复用」的地基。

### 1.1 色彩：语义优先，而非装饰优先

| Token | 值 | 语义角色 |
|---|---|---|
| `--fb-accent` `#7c5cff` | 紫 | 品牌主色 / 当前上下文 / 主操作 / 高亮节点 |
| `--fb-green` `#2fa86a` | 绿 | 正向、收入、已入账、自由、达标（ok） |
| `--fb-amber` `#e0922f` | 琥珀 | 待处理、草稿、预警（warn） |
| `--fb-red` `#e5484d` | 红 | 负向、支出、超支、危险（over/danger） |

关键设计逻辑：**颜色是信息载体，不是点缀**。每一类语义色都有 `soft`（12% 透明度底色）伴随，用于状态条/药丸/单元格底色，形成「主色 + 浅底」的稳定配对。

> ⚠️ 配色取向说明：此处「收入=绿、支出=红」遵循的是 **「绿=安全/好、红=危险/坏」的通用金融直觉**，与 A 股「涨红跌绿」的约定相反。个人记账场景下用「绿好红坏」是合理且更国际化的选择，但需与用户既有认知/插件其他模块保持一致。

### 1.2 圆角 / 阴影 / 边框：分层触感

- 圆角三级：`--fb-radius` 12px（卡片外壳）/ 8px（内部元件）/ 999px（药丸按钮）。
- 阴影两级：`--fb-shadow`（静止）→ `--fb-shadow-hover`（悬浮），悬浮态明显「浮起」，提供清晰的 hover 反馈。
- 边框统一用 `rgba(15,18,25,0.10)` 的低对比描边，避免硬黑线，贴合 Obsidian 的轻量质感。

### 1.3 明暗主题机制

- 所有表面/文字色都是变量；`.theme-dark` 类挂在 `body` 上即可整体翻转（第 44–57 行）。
- 原型栏用 `color-mix(in srgb, var(--background-primary) 86%, transparent)` + `backdrop-filter: blur()` 做半透明毛玻璃顶栏。
- 变量名刻意对齐 Obsidian 原生变量（`--background-primary`、`--text-normal`、`--text-muted`、`--text-faint`），说明这套 token 是为**直接对接 Obsidian 主题变量**而设计的，降低落地成本。

### 1.4 字体与数字

- `--font-ui`（系统 UI 字体栈）+ `--font-mono`（等宽，用于账户/金额/日期）。
- 金额、统计普遍用 `font-variant-numeric: tabular-nums`，保证数字列对齐——这是财务界面的基础可读性原则，原型贯彻到位。

## 2. 统一组件语法（Unified Component Grammar）

这是原型最值得肯定的设计逻辑：**所有块共享同一套「视觉词汇」**，读者在不同块之间切换时无需重新学习布局。

### 2.1 卡片外壳 `.finance-block`

每个块都是 `border + 12px 圆角 + 轻阴影 + hover 浮起` 的卡片。统一外壳 = 统一「这是一个独立财务组件」的心理暗示。

### 2.2 头部三件套 `.fb-head` = 图标 chip + 标题 + 状态 pill

```
[ 28px 图标圆角块 ]  标题（flex:1）        [ 状态药丸 ]
```

这一结构在 **6 个块中全部复用**（复式分录、交易流水、计算器、预算、热力图、进度仪表），是整族的「视觉指纹」。状态 pill 用 `is-accent / is-green / is-amber` 三态变体表达「当前账目 / 已自由 / 草稿 / 尚未自由 / 进行中」等。

### 2.3 可复用的子组件库

| 组件 | 用途 | 复用证据 |
|---|---|---|
| `.fb-btn` / `.is-cta` | 按钮，主操作高亮为紫填充 | 入账、批量入账、汇总转结 |
| `.fb-pill` | 状态药丸 | 各块头部 |
| `.fb-banner` | 状态横幅（free / not-free） | 计算器、进度仪表 |
| `.fb-grid` + `.fb-metric` | 指标卡片网格 | 计算器、进度仪表 |
| `.bc-summary` | 收支汇总条 | **跨块复用**：复式分录 & 交易流水（第 252 行注释明确「流水内复用」） |

> 逻辑提炼：**组件级复用 > 页面级复制**。`.bc-summary` 一次定义、两处语义自洽使用（已入账态统计 / 流水动态统计），正是 token + 组件化思路的回报。

## 3. 六大视图块的设计逻辑

### ① `fin-beancount` 复式分录 —— 真源与「草稿/已入账」双态

设计重心在**状态机的视觉表达**，是全原型最复杂的一块。

**A. 草稿态**
- 交易卡片化（`.bc-txn`），每条显示 日期 chip + 摘要 + 待入账 flag + 借贷 posting + 元数据标签。
- 草稿交易用 `border-left: 3px solid amber` 左侧色条 + `is-draft` 标识——用「左边框色条」作为「待办/需关注」的通用视觉信号（该信号在流水块 `.log-row.is-draft` 也复用）。
- 顶部操作栏放「+添加 / 入账 / 批量入账」，底部 `✓ 零和校验通过` 强调复式记账的**借贷平衡约束**（这是 beancount 的本质规则，UI 显式呈现）。

**B. 已入账态 · 账本位置 4 态（核心设计决策）**

原型用 4 张卡片穷举了账本流转的 4 种位置：

| 状态 | 承接转结 | 是否已转结 | 头部 | 底部账本链 | 汇总转结按钮 |
|---|---|---|---|---|---|
| 1 | 无 | 否 | 「当前账目」 | 无 | 有 |
| 2 | 无 | 是 | 无 | → 新账本 | 无 |
| 3 | 有 | 是（中间账本） | 无 | 旧→**本**→新 | 无 |
| 4 | 有 | 否（最新账本） | 「当前账目」 | 旧→**本** | 有 |

关键重构逻辑（第 420–421 行注释）：
- **转结信息从「纯 → 符号」改为「账本流转链」（节点 chip + SVG 箭头，箭头指向时间前方），并移至底部**；
- **当前节点高亮**（`is-this`，紫色浅底），其余为中性；
- **「当前账目」保留在头部**；
- **「汇总转结」按钮仅当前账目有**。

> 设计意图：把抽象的账本承接关系从「符号」升级为「空间化的链路」，降低多账本用户的认知负担；同时通过「按钮只在当前账目出现」避免误操作。

### ② `finance-log` 交易流水 —— 时间线式投影

- 按**日倒序**分组（`.log-day` 带圆点前缀），组内行式布局：`[点] 摘要/账户流 [右侧金额+分类]`。
- 提供**筛选 + 实时统计**：全部/收入/支出/草稿 四个过滤按钮，切换时 JS 实时重算并显示「收入/支出/净额」，且**草稿不计入收支**（第 904 行 `if (draft) return`），符合「未确认即不入账」的记账纪律。
- 与①的桥接：①的复制按钮拷贝 beancount 代码块，注释写明「用于 finance-log 精准查询」——体现「真源 → 视图」的查询链路。

### ③ `finance-ficalc` 财务自由计算器 —— 交互式工具

- 三滑块（年利率/本金/年花费）+ 复选（用实际年花费）+ 状态横幅 + 指标网格 + **敏感性矩阵**（利率轴 × 本金轴，单元格用 `c-fi/c-danger/c-warn/c-ok` 着色表达「自由/当年耗尽/预警/安全」）。
- 逻辑内核是 **FIRE 4% 法则**：所需本金 = 年花费 / 年利率（12万/4% = 300万），「可撑年数 ∞」= 收益恰好覆盖花费、本金永续。

### ④ `finance-budget` 预算执行率

- 分类行：`分类 + 已花/预算 + 百分比 + 进度条`，三档着色 `ok/warn/over`（绿/琥珀/红），超支时进度条封顶 100% 并转红——用**进度条封顶 + 色彩越界**双重表达超支。

### ⑤ `finance-heatmap` 分类 × 周 支出热力图

- 矩阵：行=分类，列=周；单元格背景用 `rgba(47,168,106, α)` 的**单一绿色透明度梯度**表达支出强度（非红绿双色），配渐变图例。
- 逻辑：热力图只表达「量」不表达「正负」，故用单色梯度比双色更不易误读。

### ⑥ `finance-fi` 财务自由进度仪表

- 顶部进度条（86%）+ 状态横幅（预计 2031 达成）+ 指标网格，是③计算器的**仪表盘化呈现**（展示态而非输入态）。
- 底部 `fi-hint` 明确标注「样本不足 12 个月，年花费为估算」——**主动暴露数据置信度**，是诚实的数据呈现。

## 4. 数据架构逻辑（最关键的「设计」层面）

原型不止是视觉，它隐含了一条**数据拓扑**：

```
        ┌─────────────┐
        │ fin-beancount │  ← 唯一真源（复式分录，借贷平衡）
        └──────┬──────┘
               │ 复制代码块 → 精准查询
               ▼
        ┌─────────────┐
        │  finance-log  │  流水视图（时间线投影）
        └─────────────┘

   fin-beancount ──派生──► budget / heatmap（支出分析）
   ficalc（输入工具）──► fi（进度仪表，展示态）
```

设计逻辑要点：
1. **单一真源**：所有视图从 beancount 派生，避免多源不一致（理念正确）。
2. **角色分层**：录入/真源（①）→ 查询投影（②）→ 分析（④⑤）→ 目标测算（③⑥）。
3. **桥接而非耦合**：①→② 用「复制代码块」做松耦合桥接，而非强制联动。

## 5. 交互与可访问性

- **主题切换**：`theme-dark` 类切换 + 按钮文案同步。
- **复制反馈**：clipboard API + `execCommand` 兜底 + 1.2s 勾选动画（`.copied`）。
- **实时筛选**：finance-log 的 filter + 动态统计 + 空分组自动隐藏（第 887–893 行）。
- **可访问性**：`role="group"` + `aria-label`、数字 `tabular-nums` 对齐、`@media (prefers-reduced-motion: reduce)` 关闭过渡动画。
- **响应式**：指标网格 `repeat(auto-fit, minmax(132px,1fr))`、reading 列 `max-width:780px` 模拟 Obsidian 阅读宽度。

## 6. 可商榷 / 可改进点（供核对）

1. **真源一致性未闭环（原型局限，但值得指出）**：①声明 beancount 为唯一真源，但③与⑥的样例数据彼此不吻合——
   - ③：本金 300万、缺口 288万 ⇒ 隐含当前本金 ≈ 12万；
   - ⑥：当前净值 258万、目标 300万、缺口 42万 ⇒ 当前本金 ≈ 258万。
   两块的「当前本金」假设相差极大。作为原型可接受，但若要体现「真源派生」，应让⑥的数值由①/③驱动而非硬编码。

2. **超支进度条封顶 100% 会丢失信息**：购物 126.2% 显示为 100% 满条，百分比文字才体现超支，视觉上弱化了「超很多」的感知。可考虑超支段用红色溢出填充或条纹。

3. **热力图单色梯度在暗色下对比偏弱**：绿色透明度叠加在深背景上，低值单元格可能与底色区分度不足，建议暗色下提高基础明度。

4. **`is-red` 药丸变体缺位**：定义了 red token 但 `.fb-pill` 无 `is-red`，目前红仅用于金额，若未来需「超支/逾期」状态药丸需补。

5. **ficalc 滑块为展示态**：`value` 写死、无 JS 联动重算，复制代码块/筛选是「真交互」，计算器是「静态示意」。原型阶段合理，落地时需补计算逻辑。

## 7. 提炼：这份设计贯彻的设计原则

1. **Token 驱动、主题无关** —— 一眼可对接 Obsidian 原生变量。
2. **统一组件语法** —— 头部三件套 + 复用子组件，跨块零学习成本。
3. **语义着色系统化** —— 紫/绿/琥珀/红各司其职，主色必配 soft 浅底。
4. **状态即布局** —— 草稿/已入账、4 种账本位置，都用「边框色条 + 按钮显隐 + 链路节点」把状态变成空间结构。
5. **信息密度分级** —— 摘要/明细/元数据三层，hover 才浮起，默认克制。
6. **真源派生、视图分层** —— beancount 为真源，其余为投影，桥接松耦合。
7. **诚实呈现** —— 草稿不计入、样本不足主动标注。

## 8. 已确定设计点（数据层 / 行为）

除渲染层设计外，本插件在「索引与启动行为」上已确认一条关键设计原则，与 §4「数据架构逻辑」互为表里：

- **账本按路径直读，不扫描全库**：`fin-beancount` 唯一真源落在 `ledgerPath` 指定的单一文件（+ `archiveLedgers` 归档），启动即按路径读取，无需遍历 vault。
- **待入账筛查默认关（零全库扫描）**：散落在笔记里的未入账草稿块，只服务于状态栏「N 笔未入账」与 finance-log 草稿分类。多数用法是「记一笔」直接入账、库内无散落草稿，因此默认**不**做全库遍历；关闭时启动只读账本文件。
- **筛查作为可选开关 + 范围限定**：开启后才扫描笔记草稿；`draftScanFolders` 非空时只扫命中的文件夹（前缀匹配，留空=全库）。范围用 getter 实时注入索引器，设置页切换即重建索引。
- **索引纯内存、不落盘**：vault 内只保留 `finance-config.json` 一个插件文件（旧版 `finance-index.json` 缓存已废弃并自动清理），换来索引永远与磁盘一致。

> 设计意图：把「全库扫描」从默认行为降级为按需开启的可选项，契合「反过度设计 / 为人服务」——只在用户确实存在散落草稿场景时才付出遍历成本。

---

> 结论：这是一份**逻辑自洽、工程落地友好**的重设计原型。其价值不仅在「好看」，更在于用一套 token + 组件语法，把 6 个异构财务块收敛成同一个可扩展的设计系统，并清晰表达了「beancount 唯一真源」的数据架构意图。主要待补强项是真源数据的端到端贯通（避免各块样例数字互相打架）与少数边缘态的视觉强化。
