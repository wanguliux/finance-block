# 02 · fin-beancount 记账语法（唯一真源）

`fin-beancount` 是 finance-block 的**唯一真源**代码块。语法是 beancount 的轻量子集，100% 合法 beancount，可脱离插件独立解析。

## 一笔交易的完整结构

````
```fin-beancount
2026-08-07 * 午餐
  现金  -3500
  费用:餐饮  3500
  type: 餐饮
  owner: 自己
^t-2026080721004501
```
````

逐行规则：

| 行 | 格式 | 说明 |
|----|------|------|
| 日期行 | `YYYY-MM-DD [flag] [摘要]` | `flag`：`*` 已入账 / `!` 待确认(pending)。摘要可空。 |
| 分录行(leg) | `  账户名  整数分 [币种]` | 缩进；金额是**整数分**（3500 = ¥35.00）；币种后缀可选（如 `USD`）。 |
| 元数据行 | `  key: value` | 缩进；`type`=分类标签，`owner`=归属；其余键进可筛选字段。 |
| 块引用行 | `^t-YYYYMMDDHHMMSSxx` | Obsidian block ref，入账后由插件附加；解析时忽略为数据行，但作为该笔的精确 ID（finance-log 的 `id` 参数据此查询）。 |

- **空行或新日期行**结束当前交易。
- 以 `;` 开头的整行为注释；行内 `;` 之后为行内注释（估值行会保留注释文本）。
- **零和校验**：一笔交易所有 leg 的金额之和必须为零，否则解析报错（`parser.err.zeroSum`，差额以分计）。

## 借贷符号

录入界面不出现 +/-，符号由**账户类别**推导（`legSignedCents` 规则）：

- `in`（余额增加）/ `out`（余额减少）。
- 资产 / 费用：增加记正、减少记负。
- 收入 / 负债 / 权益：增加记负、减少记正。

常见形态对照：

| 场景 | 写法（界面视角，填正数+方向） | 落盘 leg（分） |
|------|------------------------------|----------------|
| 花 35 午餐(现金) | `现金 out 35` + `费用:餐饮 in 35` | `现金 -3500` / `费用:餐饮 3500` |
| 工资 1 万(银行卡) | `银行卡 in 10000` + `工资 in 10000` | `银行卡 +1000000` / `工资 -1000000` |
| 微信→银行卡 转 200 | `微信 out 200` + `银行卡 in 200` | `微信 -20000` / `银行卡 +20000` |

## 跨币种

```
2026-08-02 * 美元收入
  资产:银行A  -10000 USD
  收入:工资  -10000 USD
```

带币种后缀的 leg，按 `finance-config.json` 的汇率换算到基准币种参与汇总。金额仍是整数分（USD 10000 = $100.00）。

## 估值行（市值计价账户）

```
2026-08-01 custom "fb-valuation" 投资:股票 125000000
2026-08-01 custom "fb-valuation" 投资:股票 125000000 ; 约 350 股，按收盘价
^v-2026080112000001
```

- 格式：`YYYY-MM-DD custom "fb-valuation" <账户名> <金额(分)> [币种]`。
- **不参与零和校验、不产生分录、不改余额**——只作为视图层覆盖（"这项资产现在值多少"）。
- 紧随其后的 `^v-` 行是其块引用（与交易的 `^t-` 对称）。
- 仅对 `valuation: market` 的账户有意义；`valuation: book` 的账户估值被忽略。

## 待入账草稿

笔记内 `fin-beancount` 块里、尚未点「入账」的笔，带 `!` flag 且无 `^t-` 引用，标记为草稿（`draft: true`），**不计入统计**。点「入账」后补上 `^t-` 引用并写入账本文件。

## 解析器软告警（只提示、不拦截）

- **符号可能反了**：收入/费用账户符号与常规相反（如退款冲销可忽略）。
- **账户未声明**：leg 账户不在 `finance-config.json` 的账户里，也不继承父账户类别 → 不计入资产总览/预算。
- **标签与结构不符**：`type` 声明为某方向，但交易里没有对应方向账户（如买股票却标"支出"会污染筛选）。

> 自然语言记账走 `scripts/append_entry.js`：你只需给出「账户 + in/out + 元」，脚本自动按上述规则推导符号并做零和校验（见 `07-nl-recording.md`）。
